# Docgraph v1.0

<a id="s-S34QTXZT11"></a>
## Objective

Ship the first release that makes an explicit compatibility commitment for
docgraph's repository-facing contract rather than treating compatibility as best
effort.

<a id="s-XHXCWTTW9K"></a>
## Current blockers

- [Bootstrap docgraph repositories](../issues/bootstrap-docgraph-repositories.md).
- [Publish a docgraph validation action](../issues/publish-validation-action.md).
- [Version and verify the portable agent skill](../issues/version-portable-agent-skill.md).

These issues are authoritative blockers through their managed `affects` relations,
not through the Markdown links alone.

<a id="s-T1CMMMPHPV"></a>
## Additional work required

- Accept a v1 compatibility decision that names the stable surfaces and defines
  semantic-versioning, deprecation, migration, and incompatible-schema behavior.
- Turn that decision into conformance coverage for the supported configuration,
  managed-frontmatter, CLI, JSON-output, and logic contracts, including explicit
  handling of pre-1.0 repositories.
- Define the v1 release contract and acceptance boundary, then build and validate
  the supported artifacts from clean environments.
- Update package metadata and user documentation for the compatibility-guaranteed
  release and perform a final milestone-readiness audit.

The completed reference roadmap reports no other untracked implementation gap.
Additional product features, targets, packaging channels, remote enrichment, and
semantic merge remain demand-driven rather than implicit v1 requirements.
